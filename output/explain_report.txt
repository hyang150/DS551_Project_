############################################################
# Q1_50day_MA: 50-day moving average (window function)
# Focus: Vectorized Execution
############################################################

SQL:
SELECT
                Date, Symbol, Close,
                AVG(Close) OVER (
                    PARTITION BY Symbol
                    ORDER BY Date
                    ROWS BETWEEN 49 PRECEDING AND CURRENT ROW
                ) AS MA_50
            FROM stock_data
            ORDER BY Date DESC
            LIMIT 100

--- Internals -> Application Mapping ---
DuckDB: STREAMING_WINDOW operator batches AVG over 2048-tuple chunks and benefits from SIMD acceleration.
MySQL: iterates the window frame row-by-row, paying function-call overhead per row.

# Q2_daily_volatility: Daily volatility — narrow projection (3 cols)
# Focus: Columnar Storage — Column Pruning
############################################################

SQL:
SELECT
                Date,
                Symbol,
                ROUND((High - Low) / Close * 100, 4) AS daily_volatility_pct
            FROM stock_data
            ORDER BY daily_volatility_pct DESC
            LIMIT 100

--- Internals -> Application Mapping ---
DuckDB: reads only the High/Low/Close column segments, skipping Open/Volume/Symbol/Date — about 57% less I/O.
MySQL: row store must fetch the whole tuple and discard unused columns.

# Q3_annual_summary: Annual summary (GROUP BY + multi-aggregate)
# Focus: Vectorized Aggregation
############################################################

SQL:
SELECT
                YEAR(Date)   AS Year,
                Symbol,
                ROUND(AVG(Close),  2) AS avg_close,
                ROUND(MAX(High),   2) AS year_high,
                ROUND(MIN(Low),    2) AS year_low,
                SUM(Volume)           AS total_volume
            FROM stock_data
            GROUP BY YEAR(Date), Symbol
            ORDER BY Year, Symbol

--- Internals -> Application Mapping ---
DuckDB: PERFECT_HASH_GROUP_BY / HASH_GROUP_BY operators hash + aggregate batches of values inside each vector chunk.
MySQL: row-by-row read -> hash -> update aggregate state; cache misses dominate.
